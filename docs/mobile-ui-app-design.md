# CC Remote 手机 App UI 与体验设计

## 设计判断

CC Remote 不是普通聊天 App，也不是营销型 AI 助手。它是手机上的本机 Claude Code 遥控器。用户打开它时，关心的是电脑还在不在线，当前任务有没有跑，发出的 prompt 会作用在哪个工作目录。

界面要像一个安静可靠的控制台。它可以有质感，但不能炫。它要比聊天软件更克制，比运维面板更亲近。第一版不追求功能堆满，而是把扫码配对、连接状态、发送 prompt、流式输出、停止任务和退出配对做稳。

设计读法是 native mobile devtool for one owner。视觉语言是 light glass control console。设计系统倾向 Apple HIG 的克制、iOS 毛玻璃材质和 Material 的清晰状态表达。视觉拨盘设为 `DESIGN_VARIANCE 5`，`MOTION_INTENSITY 3`，`VISUAL_DENSITY 6`。这意味着布局不能太花，动效只服务状态变化，信息密度比普通消费 App 更高。

## 第一版边界

第一版只服务一台电脑、一个 token、一个 Claude Code session。没有多电脑管理，没有历史云同步，没有文件上传，没有权限审批 UI，没有后台通知，也没有主题切换。

这些功能以后都可能有价值，但现在会污染主路径。第一版的判断标准只有一个。手机扫码之后，能稳定控制本机 Claude Code，并且用户随时知道当前连接和任务状态。

## 视觉气质

整体采用浅色柔和渐变。主背景从雾白过渡到冰蓝、浅青和极淡薰衣草灰，像清晨玻璃上的冷光，不是彩虹糖渐变。页面要明亮、干净、有空气感，但不能变成营销页。这个产品的高级感来自状态清楚、层次透明、文字干净。

核心材质是毛玻璃。主面板使用半透明乳白，背后有轻微模糊和高光边。边线用白色高光和浅灰描边叠出厚度。阴影要轻，像浮在渐变背景上，不像卡片掉在桌面上。玻璃层级最多两层，禁止玻璃卡片套玻璃卡片。

推荐色彩方向是浅色渐变加单一青蓝强调。青蓝用于已连接、运行中、发送按钮和成功反馈。停止任务使用低饱和珊瑚红，只在任务运行时出现。断线和错误使用柔和琥珀或玫红灰，但不要让整页变成警告页。

形状系统保持一套规则。主面板圆角在 18 到 22。输入框和消息块圆角在 14 到 18。按钮可以更圆，但不要全局胶囊化。不要卡片套卡片。页面主结构靠玻璃层级、留白和细线分区，不靠一堆浮层堆叠。

字体使用系统字体。iOS 使用 SF，Android 使用 Roboto。代码、日志、路径、退出码使用等宽字体。标题控制在中小尺寸。这个 App 不需要巨大的品牌标题，手机工具的可信度来自密度和秩序。

## 全局结构

App 不使用底部 Tab。第一版没有足够多的平级模块，Tab 会制造不存在的信息架构。启动后根据本地 token 和 daemon 状态进入不同路径。没有 token 时进入配对。已有 token 且 status 可用时进入控制台。设置作为控制台上的半屏 sheet 打开。

页面路径是启动判定、扫码配对、配对确认、主控制台、设置 sheet。异常状态不另开复杂页面，而是在当前路径内给出可恢复动作。token 失效回到配对。网络断开留在控制台并禁用输入。Claude 正在运行时保持控制台，并把停止操作提升到输入区。

## 启动页

启动页只承担检查状态，不做欢迎和品牌教育。画面中心放 CC Remote 的小标题和一行状态文案。状态文案按真实过程变化。先是读取本地配对信息，再是检查电脑 daemon，再是恢复连接。

加载形态不要用普通圆形 spinner。可以用一条细窄的状态线，或三段文字的渐进高亮。动效轻，不要循环过度。启动成功后过渡到控制台。启动失败时不要弹窗，直接进入相应的配对或断线状态。

imagegen 画面应表现一个浅色渐变手机界面，中央内容少，文字安静，背景有细腻的冷光渐变和毛玻璃质感。不要装饰球，不要彩虹渐变，不要大面积霓虹。重点是稳定启动中的控制台感。

## 扫码配对页

配对页是新用户第一眼。它要像配对可信设备，不像登录页。上方显示 CC Remote 和一句扫描电脑终端里的二维码。中间是扫描框。扫描框占屏幕宽度的大部分，但边界克制。四角可以有轻微青蓝高亮，中央保持干净，让相机画面成为主视觉。

扫描框下方显示二维码有效期和服务地址提示。文案要短。不要放操作教程堆叠，也不要用三步说明撑满屏幕。用户已经知道自己要扫码，界面只需要确认扫的是 CC Remote 的配对码。

扫到二维码后，进入配对确认 sheet。不要立刻换 token。确认 sheet 显示设备名、服务地址和二维码是否仍有效。用户点击连接后才调用 `/api/pair`。这样能避免扫错码时毫无反馈。

imagegen 画面要强调真实相机扫描区域和底部毛玻璃确认控件。不要做插画。不要做彩色二维码示意图。配对页的情绪是谨慎、短促、可信。

## 配对确认

配对确认是一个底部毛玻璃 sheet。顶部显示设备名，比如 Jayson PC。下面显示 origin，比如 `https://tbhaoshuai.ccwu.cc`。再显示过期状态。主按钮是连接这台电脑。次要按钮是重新扫描。

如果二维码过期，主按钮不可用，状态文案改为二维码已过期，请重新生成。这里不需要解释 Cloudflare Tunnel，不需要解释 token。用户此时只需要知道能不能连。

配对成功后不要进入庆祝页。显示一个短暂的已连接状态，然后滑入主控制台。过渡时间控制在半秒内。

## 主控制台

主控制台是核心页面。顶部是连接头，中间是 transcript，底部是 prompt bar。页面不需要欢迎 hero，不需要功能卡，不需要大面积说明。

连接头不是普通 AppBar。左侧显示设备名，下一行显示工作目录尾部或项目名，比如 `cc-remote`。右侧显示连接状态和设置按钮。连接状态使用真实语义色，已连接为青蓝，正在连接为灰蓝，电脑端离线为克制红灰，鉴权失效为玫红灰。状态点只在连接头使用一次，禁止在列表和按钮里重复装饰。

连接头下面是一条会话状态带。新会话时显示新会话。已拿到 Claude session id 时显示已续接会话。运行中时显示 Claude 正在运行，并把 Stop 入口提升。电脑端离线时同一位置显示重新连接。这样用户不会到处找状态和修复入口。

Transcript 区域不是微信式聊天流。用户消息可以靠右，但不要做过窄气泡。Claude 输出靠左，更像代码审阅和终端输出。消息块使用半透明玻璃面、轻边框和小圆角，背景略高于页面。系统消息是细小中间行，例如已停止、已恢复连接、token 已失效。

底部 prompt bar 固定在安全区上方。文本框默认两行高度，最多扩展到四行。发送按钮在右侧。空输入时禁用。运行中时发送禁用，Stop 出现在同一操作区。Stop 要在拇指可达区域，不要藏到顶部或设置里。

imagegen 画面要抓住这个结构。顶部状态、中央真实文本输出、底部输入和停止控制。不要把它画成普通聊天 App。不要用头像。不要用花哨 AI 助手形象。

## 运行中状态

运行中状态必须明显，但不能焦虑。连接头保持已连接，会话状态带变成 Claude 正在运行。底部发送按钮禁用，Stop 按钮可用。当前 assistant 消息下方出现轻微的流式状态线。

不要使用三个跳动圆点。它太像客服聊天。更合适的是一条细窄的青蓝脉冲线，或消息块底部的一段玻璃高光扫过。动效必须很轻，减少动效时直接静态显示运行中。

如果用户点击 Stop，按钮进入停止中。停止成功后系统消息显示已停止。停止失败时保持运行状态，并显示错误。

## 输出与代码块

Claude 输出默认支持 Markdown。正文保持可读行距。代码块可以使用浅墨色内嵌块，和整体浅色玻璃形成对比。代码块使用等宽字体，顶部显示语言名和复制按钮。复制按钮只出现在代码块内部，不要每条消息都带一排操作。

移动端代码横向滚动可以接受。不要强行把代码自动换行到难读。长输出时 transcript 保持滚动到底部，但用户手动向上滚动后不要强制拉回底部。当前流式消息可以提供一个回到底部的小浮动按钮，但第一版可以先不做。

错误输出和 stderr 不要混入普通 assistant 消息。错误使用系统消息或错误块。错误块颜色克制，文案给出下一步动作。比如 Claude CLI 未找到时，显示电脑端找不到 Claude CLI。不要把长 stderr 全量铺满页面。

## 空状态

第一次进入控制台且没有 transcript 时，中央只放一句本机已连接，可以发送任务给 Claude Code。下面可以放三个短 prompt chip。建议是检查这个项目、运行测试、总结当前目录。

Prompt chip 是辅助入口，不能抢底部输入框的权重。chip 使用轻边框，点击后填入输入框，不自动发送。不要放一堆营销文案，不要介绍功能，不要加学习成本。

## 断线状态

断线或电脑端 daemon 停止时不要把用户踢回配对页，除非 token 已失效。主控制台保留 transcript，输入区禁用，状态带显示电脑端离线。右侧提供重新连接。断线期间如果 Claude 仍在电脑端运行，App 不承诺补回输出。

断线画面要稳。不要满屏红色。不要弹系统式大错误弹窗。用户最需要的是知道旧内容还在，以及下一步怎么恢复。

## 鉴权失效

token 失效时说明这台电脑已要求重新配对。主操作是重新扫码。此时应清理本地 token。旧 transcript 可以留在内存直到用户离开页面，但不写入持久历史。

这个状态语气要中性。不要说登录失败。它不是账号系统。更准确的说法是配对已失效。

## 设置 Sheet

设置用半屏毛玻璃 sheet。不要做完整设置页。内容只放设备名、服务地址、工作目录、连接状态、会话状态、重新连接、退出配对。

退出配对需要确认，因为它会撤销 daemon token。确认文案要短，说明退出后这台手机需要重新扫码。不要在这里放主题切换、App 版本、隐私说明、帮助中心。第一版不需要这些入口。

## 交互动效

页面切换使用 180 到 220 毫秒的横向滑入或淡入。sheet 使用系统手感的上滑。按钮点击有轻微下压反馈。状态变化用淡入和轻微位移。所有动效只服务状态变化，不服务炫技。

禁止大面积粒子、霓虹扫描、滚动视差、3D 卡片、廉价玻璃拟态。毛玻璃只能服务层级和触感，不能把每个元素都做成亮晶晶的贴纸。这个 App 的语气是可信工具。越花越不可信。

## 文案规则

文案要短。一个状态一句话。一个按钮一个动作。不要解释技术原理，除非错误需要用户修复电脑端配置。

推荐使用连接、重新连接、停止、退出配对、重新扫码、已续接会话、新会话、运行中这些词。避免欢迎回来、开始创作、释放效率、智能助手、下一代工作流这类营销口吻。

路径、origin、session id、退出码这类内容使用等宽字体。用户能复制的内容要明确，但不要到处放复制按钮。

## Imagegen 生成方向

后续用 imagegen 生成概念图时，先生成完整手机屏幕，不要先生成零散组件。最先需要四张主图。第一张是启动检查。第二张是扫码配对。第三张是主控制台空状态。第四张是运行中 transcript。

每张图都要是竖屏手机 UI，画幅建议 9:19.5。背景为浅色柔和渐变，界面有克制毛玻璃层级，单一青蓝强调。不要头像，不要 AI 机器人，不要廉价蓝紫渐变，不要营销 hero，不要三张功能卡。

主控制台概念图要出现真实信息层级。顶部显示 Jayson PC 和 `cc-remote`。状态显示已连接、正在连接、电脑端离线或运行中。中间有用户 prompt 和 Claude 输出。底部有输入框、发送和停止。代码块至少出现一个，用来验证字体和信息密度。

扫码概念图要出现相机扫描框和配对确认状态。确认 sheet 上要有设备名、服务地址和连接按钮。不要画成登录页。

## 可实现组件边界

Flutter 代码后续可以按这些组件拆。`AppScaffold` 负责安全区、背景和全局布局。`ConnectionHeader` 负责电脑名、工作目录和连接状态。`SessionStrip` 负责新会话、已续接、运行中、电脑端离线和重连。`TranscriptView` 负责消息流。`MessageBlock` 负责用户消息、assistant 输出和系统消息。`CodeBlock` 负责代码显示和复制。`PromptBar` 负责输入、发送、停止和键盘避让。`PairScanner` 负责扫码。`PairReviewSheet` 负责配对确认。`SettingsSheet` 负责设备信息和退出配对。

这些组件够第一版使用。不要提前拆出复杂主题系统、路由框架或多设备模型。代码以后应该跟着真实功能长，不要跟着想象长。

## 设计验收

第一版 UI 能过关的标准是，用户打开 App 后三秒内知道连的是哪台电脑。任务运行时不用找就能停止。断线时知道内容没有丢，并且知道怎么重连。第一次扫码时能确认自己连的是正确的电脑。所有按钮都可读，所有状态都可解释。

如果某个画面看起来像聊天机器人、登录产品、运维大盘或 AI 官网，它就偏了。CC Remote 应该像一个握在手里的本机控制台。安静，有分寸，动作很少，但每个动作都算数。
