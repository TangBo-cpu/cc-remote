# CC Remote 手机端 UI 实现规格

## 文档状态

本文记录 Flutter 手机端的当前实现规格与验收目标。当前视觉以根目录 [`DESIGN.md`](../DESIGN.md) 的浅色 / 深色色板和共享组件为准；Penpot 的 `CCR / 01` 至 `CCR / 11` 画板保留为流程参考。

v1.4.1 使用浅色 / 深色界面，默认跟随系统。启动、配对、聊天、设置、权限、恢复和工作区使用同一套中性色；主动作使用炭黑，深色模式使用近白，选中态使用灰底与字重。正文链接采用中性色和下划线，恢复卡片里的重连按钮使用灰底深色字。输入区、浮动控件和面板使用玻璃材质，保留背景模糊、高光边缘与分层阴影。壁纸、背景预设、偏好预览与复杂启动动画已移除。模型、字号、代码复制、工具卡片与折叠历史继续可用；Android 真机界面仍待验收。

`mobile/lib/appearance_preference.dart` 管理外观持久化与切换；`mobile/lib/effort_gauge.dart` 保留思考强度仪表与模态交互。

## 目标与非目标

目标：

- 将启动、配对、聊天、设置与工作区统一到浅色 / 深色基础样式，让内容和操作清楚可读。
- 补齐配对、会话选择、运行控制、权限处理、Diff 查看与恢复状态的统一体验。
- 让连接、运行、停止、失败和断线在短暂扫视中可判断。
- 保留现有协议与安全边界，优先通过 UI 重组完成改造。

非目标：

- 不增加底部 Tab，不把手机改造成文件编辑器或终端。
- 不允许手机注册任意工作目录、执行任意 shell、暂存或提交 Git。
- 不为视觉草案虚构 daemon 尚未提供的进度、风险、错误结构或队列数量。
- 不以模仿 ChatGPT 或 Claude 为目标；只吸收其移动端的内容优先、紧凑导航和低装饰密度。

## 视觉基线

- 所有页面与弹层读取当前 `AppPalette`，默认跟随系统，设置中可固定浅色或深色。
- 基准尺寸为 390×844，页面水平安全边距 20px；小屏与大字体使用弹性布局和滚动。
- 页面与代码使用不透明阅读表面；助手正文直接排在页面上，用户消息使用浅灰气泡。输入区、浮动控件和面板使用中性玻璃材质、淡高光边缘与柔和阴影，浮动控件保留背景模糊。
- 主动作使用炭黑，深色模式使用近白；选中态使用灰底、图标与字重，正文链接使用中性色和下划线。会话导航保留彩色身份标识与蓝色导航强调色（`#3877A7` / `#87B7DB`）。成功反馈仅用小面积的低饱和状态色，错误与警告使用独立语义色；状态同时用图标和文案表达。
- UI 与助手正文使用手机系统默认字体，正文约 15px / 1.6，Diff 代码约 12–13px。
- 「字体大小」保留连续滑杆（约 0.85×–1.40×，步进 0.05，默认 1.0）；阅读缩放与系统文字缩放相乘，夹在 0.85–1.6。
- 关键状态与按钮辅助文字最低 12px；交互命中区至少 48×48px。
- chrome 用 Lucide 线性图标；会话、项目与模型身份标记用 Phosphor Fill。
- 输入聚焦使用当前强调色描边；正文、代码、链接和系统栏均随外观更新。

完整设计 token 见 [`DESIGN.md`](../DESIGN.md)。

### 设置

- 设置以扁平分组展示，保留明确的关闭动作，内容可滚动。
- 「外观」只有「跟随系统」「浅色」「深色」三个选项，选择即时生效并持久化。
- 外观变化保留会话、草稿、阅读位置和已打开的设置；系统外观变化只影响跟随系统模式。
- 模型、字体大小和通知继续可用；主机、服务和目录降为次级信息。
- 模型选择器沿用共享 `AppOptionRow` sheet 与 Phosphor Fill 身份图标。

## 页面与画板映射

### 00 Startup

用户目标：知道 App 正在恢复连接。

- 使用当前外观的纯色背景，显示应用图标、产品名和真实 `BootstrapPhase.label`。
- 不设置人为等待时间；完成恢复后进入配对或聊天。
- 屏读只播报当前恢复状态，减少动态效果时无需额外动画分支。

### 01 Pair Device

用户目标：让手机安全地连接桌面主机。

- 标题直接说明“连接你的桌面主机”。
- 扫码是主动作，手动输入配对码是次路径。
- 显示端到端传输与一次性配对说明，但不使用大角色或装饰插画占据首屏。
- 扫码成功后仍进入确认步骤，展示电脑名、origin 与二维码有效性，再调用 `POST /api/pair`。
- 错误、过期和相机权限失败必须保留“重新扫描”与手动输入入口。

### 02 Choose Session

用户目标：恢复最近任务或选择其他会话。

- 会话导航使用独立页面、系统返回与顶部紧凑新建操作；页面进入和退出遵循 Android predictive back，reduced motion 时路由时长归零。Bottom sheet / dialog 统一使用 220ms 进入 / 160ms 退出，系统减少动态效果时不播放空间转场。
- 默认视图展示当前项目会话，并保留「所有项目」入口和少量项目快捷项；完整项目列表在子视图中选择后返回会话视图。
- 项目与会话使用当前外观的扁平列表，层级由字号、分组标题、缩进和留白表达；保留 `AppMark.of(id, index)` 彩色会话/项目身份图标与独立蓝色导航强调色（`#3877A7` / `#87B7DB`）。
- 每项显示会话名、引擎和当前 / 运行状态；完整摘要保留在 transcript 与搜索结果中，不挤压高频会话列表。项目子视图保留完整路径以区分同名目录。
- 切换或创建会话在任务运行、附件上传或停止中禁用。
- 固定说明“切换会话不会中断桌面端正在运行的任务”仅在协议事实成立时显示。
- 搜索按需进入独立子视图：空态显示提示，输入后通过 300ms 防抖查询 daemon 的权威 transcript，并提供清除、重试和返回当前上下文入口。
- 匹配片段只高亮 daemon 返回的安全文本范围；结果最多 50 条。点击后复用现有会话切换，等待目标会话的权威 transcript 到达，再定位命中消息并短暂高亮对应正文或气泡；归档会话保持只读不可进入。

### 03 Run Control

用户目标：查看当前桌面任务、继续指令或停止。

页面从上到下只有三层，Composer 叠在对话上：

1. 分离式浮动会话控制（背板向下渐隐模糊，transcript 可滚入导航背后）。
2. 全高 transcript（含活动与证据）；列表底部留白让末条可读。
3. 玻璃 Composer（叠在 transcript 底部；列表底部留出输入区空间）。

顶部参考 Claude 手机端：左侧仅保留圆形菜单，右侧是新建与更多组成的短胶囊，中间不显示产品名、会话名、连接状态或设备名。非「已连接」相位时，会话头下方显示紧凑 `ConsoleStatusStrip`。模型、权限图标与上下文余量留在 Composer 工具行，路径和设备信息进入设置或 sheet。

用户消息使用中性浅灰气泡（约 0.88 屏宽），深色外观使用对应深灰表面；圆角 22px，无描边或阴影。助手正文靠左直接排在页面上，无气泡底色和外围描边。正文使用系统默认字体，搜索命中保留临时高亮。新一轮用户消息前保留 14px 间距，同一回合内紧凑衔接。Markdown 段落与列表项共用 8px `blockSpacing`；有标记时流式期间即渲染，无标记走 `Text`。代码块保留语言标签和复制按钮，使用当前控制色且无内描边。来源链接只允许绝对 `http` / `https` URL，由系统浏览器打开。连续工具活动合并为可折叠时间线，单步可展开 detail；运行中始终可见停止入口。

Composer 默认保持 32px 圆角、中性玻璃表面并避开系统手势区；键盘打开后取消底部间隙，底部两角变直并贴合 IME。键盘 inset 用于输入区状态判断，Transcript 只缩短可见高度，已有消息不随每个键盘高度帧重建。

### 04 Permission Request

用户目标：理解风险后做一次明确决策。

内容顺序固定为：

1. “允许 Claude 运行命令？”或与实际工具相符的标题。
2. 命令或工具摘要。
3. 工作目录。
4. 权限与影响。
5. 授权范围。
6. “拒绝并返回”与“仅本次允许”。

单个权限请求仍只允许一次或拒绝，不得包装成永久授权；权限模式默认自动判断，更改后对当前会话的后续各轮生效，并在切换或新建会话时读取对应会话设置。

当前协议只稳定提供 `toolName`、`detail`、`title`、`displayName`、`description` 和 `decisionReason`。工作目录优先取当前会话 `workspaceDir`；缺失时显示「以桌面主机当前工作区为准（路径暂不可用）」，不虚构绝对路径。风险分级和影响条目必须由可验证字段推导；信息不足时显示保守的工具说明，不虚构“不会访问密钥”等承诺。若产品需要更结构化的风险项，应单独扩展协议并增加 daemon/Flutter 测试。

### 05 Review Diff

用户目标：快速理解桌面工作区变更。

- 顶部显示文件数与增删摘要；默认统一视图。
- 按文件导航，支持跳到变更与错误行。
- 代码采用等宽字体，12–13px，行高至少 1.45；长行允许水平滚动或安全换行。
- 明确“变更仅保存在桌面工作区；手机端不会自动提交”。
- 保持只读，不增加暂存、提交或编辑。

现有 `WorkspaceDrawer` 和 `/api/workspace/diff` 可作为数据源；若要得到可靠的总增删数量，应从 diff 文本解析并测试，而不是在 UI 中估算。

### 06 Offline Recovery

用户目标：确认内容未丢并恢复连接。

- 会话头显示“连接已断开 / 记录已保留”。
- 正文明确手机无法连接哪台主机，恢复后将从权威快照继续同步。
- 恢复卡只有一个主动作“立即重连”。
- Composer 降级为离线状态面，保留草稿和附件，并显示“离线”。

客户端现由 `RemoteWebSocketClient` 发布自动重连次数、下一次重试时间与最近传输错误；面板显示“自动重连第 N 次”和预计等待时间，错误只映射为固定安全摘要，不展示原始 URL、设备或异常文本。“立即重连”取消当前退避 Timer 并建立新一代连接；只有收到 authenticated `status` 才清零连续重试次数。待发送数量仍只能统计本地尚未收到 `prompt_accepted` 的内容。

### 07 Task Failed

用户目标：理解失败原因并选择恢复动作。

- 明确任务在哪个阶段停止、工作区是否保留。
- 显示 daemon 提供的错误原文或安全化摘要。
- 主动作“查看错误并重试”；次动作“查看当前 Diff”进入更多菜单或弱化位置。
- 不根据错误字符串猜测精确文件行号，除非解析器有测试覆盖。

### 08 Stopping

用户目标：确认停止请求已经发送且无需重复点击。

- 显示“停止请求已发送”“正在停止”和已等待时长。
- 停止按钮禁用，使用方形 stop 图标与“等待主机确认”文字。
- 不允许再次提交停止请求。

### 09 Stopped

用户目标：确认桌面任务已真正结束。

- 只有收到 WebSocket `stopped`，或权威 transcript 中保留了明确“已停止”终态证据后进入。普通 `running: false` 只能证明任务不再运行，不能区分完成、失败与停止。
- 显示工作区和 transcript 仍保留。
- Composer 恢复发送能力，主动作可为“继续告诉 Claude”。

### 10 Stop Timeout

用户目标：理解手机没有收到确认，不误判为已停止。

- 本地等待超时后显示“停止超时 / 主机未确认停止”。
- 任务仍按运行中处理，允许再次发送停止请求或查看详情。
- 不将 `running` 清为 false，不显示“已停止”。

现有 `stopRun()` 已在网络超时后追加“停止请求未确认，任务仍在运行”，可以直接映射此画板。

### 11 Reconnect Failed

用户目标：知道自动恢复失败后还能做什么。

- 显示最后一次连接结果和已保留内容。
- 主动作“再次重连”；次路径进入配对或连接诊断。
- 当前客户端持续重试且没有耗尽终点，因此不显示伪造的失败终态；连续 6 次后提示检查电脑端服务和网络，自动重连退避上限仍为 30 秒；后台持续至少 60 秒回到前台时会先强制重建 WebSocket。

## 共享组件

### CompactSessionHeader

- 当前实现由 `ConnectionHeader` 承担，不保留 `LegacyConnectionHeader`。
- 高度 48px，使用薄玻璃控制表面；通过 `_ChatOverlayLayout` 浮动在 transcript 上方，正文可滚入其背后。
- 背板由 `_ChatTopBackdrop` 提供（ClipRect + ShaderMask dstIn + BackdropFilter sigma 12，向下渐隐，主题 paper alpha 0.36），并通过 IgnorePointer 与 ExcludeSemantics 避免拦截手势。
- 导航按钮单独处于 SafeArea 中，菜单、新建与更多操作保持 48dp 触摸区。
- 顶部 chrome 不重复显示产品名、会话名、连接状态和设备名；非 `ConsolePhase.connected` 时在头下方渲染 `ConsoleStatusStrip`，断线时展示恢复卡片。
- 设备与路径分流到设置或 sheet；模型保留在 Composer，“···”菜单底栏最多显示模型名，不显示剩余上下文 token。
- `_ChatOverlayLayout` 动态测量导航、状态条与恢复卡片高度，并向 `TranscriptView` 传递 `topPadding`；阅读字号缩放不影响导航头与状态面板高度。

### TranscriptView

- 保留现有本地缓存、snapshot 覆盖与流式轻渲染逻辑。
- 采用全高滚动视口，正文可滚动至屏幕最顶部及导航栏背后，消除原水平硬裁切。
- 初始列表与空状态顶部 padding 由 `_ChatOverlayLayout` 动态计算提供，确保首行停留在导航与状态卡下方。
- 全文搜索 `scrollToRow` 通过 `RenderAbstractViewport` 动态计算目标偏移，扣除顶部遮罩高度，保证命中消息停留在导航下方。
- 用户消息靠右使用无描边浅灰气泡；助手回复靠左直接排在页面上；系统消息用次级文字展示。
- 空状态三分支：已连接快捷芯片 / 离线 `_OfflineReconnectCard` / 连接中 `_ConnectingStatusCard`。
- 权限请求为全宽决策面，顺序为命令 → 工作目录 → 影响 → 范围 → 动作。

### ActivityEvent

- 复用现有 `ActivityKind` 与 `ActivityState`。
- 当前 running 事件为完整卡；done/stopped 事件默认折叠；error 事件保留错误摘要。
- thinking running 使用固定中心的花形帧动画：圆点生长为四瓣 / 六瓣 / 八瓣星芒后收回，文字位置不移动；显示「本轮已运行 N 秒」。关闭系统动画时固定为完整花形，屏读只在进入状态时播报一次「正在思考」。其他活动 running 使用 `CircularProgressIndicator`。
- 任务轨只在活动局部出现，不贯穿整屏。

### Composer

- 悬浮叠在 transcript 底边：`ChatScreen` 用 `Stack` 全高铺对话，顶部 `_ChatOverlayLayout` 浮动导航，底部 `PromptBar` 底对齐；列表/空状态底部 padding 约 188，避免末条被挡住。
- 标准最小高度约 110px，圆角 `composerFloat`（32px），使用中性强玻璃表面、淡高光边缘与柔和阴影。
- `SafeArea(bottom: false)`，底边用 `MediaQuery.viewPadding.bottom`（无手势条时回退 8）抬离系统指示条。
- 上方是可增长文本区；下方保留附件、思考强度、模型、权限、上下文余量和发送 / 停止。窄屏优先收缩模型文案。
- `+` 使用独立浅灰圆形底座，只打开附件；工具行不使用共同的灰色底板。权限图标打开既有权限 sheet（含 bypass 二次确认），保留完整 tooltip 与屏读语义。
- 思考强度模态层恢复全屏背景模糊和径向光层，仪表保留刻度、指针阴影与高光。沿圆弧滑动吸附五个手动档位，点击中心切回自动，松手提交，点击空白关闭。
- 模型选择使用紧凑模型胶囊；打开后是共享 `AppOptionRow` sheet，身份图标为 Phosphor Fill。
- 权限图标旁以无底色浅灰细环和剩余百分比显示上下文，深灰短弧表示已消耗比例；完整 token 数保留在 tooltip / 屏读语义中，上下文数据不改变指令建议区高度。
- 视觉控制可为 36px，实际命中区至少 48px。
- 附件预览显示在输入台内部的可滚动短条，使用浅灰表面和淡边框，不改变核心控制顺序。正文文件卡使用独立的中性图标底座。
- 斜杠指令建议限制在最多三个首选项，完整结果可继续滚动。

### PermissionDecision

- 一次只能处理一个待审批请求。
- 操作期间禁用按钮并提供进度。
- 收到 `permission_resolved` 或 `permission_expired` 后关闭。

### RecoveryState

- 06、07、08、09、10、11 复用相同状态标题、事实说明、证据和单一主动作位置。
- 状态必须使用图标、文字和色调三重编码。
- 当前 `RecoveryStatePanel` 已覆盖连接中、断线、失败、停止中、停止未确认和已停止；断线态读取传输层快照显示尝试次数、预计重试时间与安全错误摘要，正常对话时隐藏，不恢复常驻顶部状态栏。
- 连接中与断线空状态不再各自维护大卡片，避免与头部状态重复；等待权限仍使用紧凑 `ConsoleStatusStrip` + 权限决策面。

| UI 状态 | 现有事实来源 | 允许的主动作 | 关键约束 |
|---|---|---|---|
| 连接中 | `!wsReady && !remoteOffline` | 等待；空 transcript 显示连接卡 | 状态条显示「正在连接」；不与离线卡混用 |
| 已连接 | `wsReady && !running` | 发送、新建、切换 | 状态条隐藏 |
| 运行中 | `running && !stopping` | 停止 | 停止入口始终可见 |
| 停止中 | `running && stopping` | 无，等待确认 | 禁止重复停止 |
| 已停止 | WebSocket `stopped` 或权威 transcript 的明确停止证据 | 继续输入 | 普通 `running: false` 不足以判定 |
| 停止超时 | `running && !stopping` 且最近停止请求超时 | 再次停止 | 仍视为运行中 |
| 离线 / 自动重连 | `remoteOffline` + `RemoteConnectionSnapshot` | 立即重连 | 面板显示真实尝试次数、预计重试时间和安全错误摘要；transcript 与非空草稿分别说明 |
| 重连失败 | 明确的重试耗尽事实 | 再次重连 | 当前没有耗尽策略，因此不生成此终态 |
| 失败 | WebSocket `error` 或失败终态 | 查看错误并重试 | 保留原始错误证据 |
| 等待权限 | `pendingPermissions.isNotEmpty` | 允许一次或拒绝 | 一次处理一个请求；权限卡展示 `workspaceDir` |
| 上传中 | `uploadingAttachments` | 取消或等待 | 禁止切换会话与发送 |

UI 直接把这些事实映射为当前视图，不引入新的全局状态机对象。只有当 `main.dart` 的布尔组合持续产生冲突，才拆出独立 controller。

## 图标规范

chrome 使用 `lucide_icons_flutter`；会话、项目与模型身份标记使用 `phosphor_icons` Fill。项目行与标题共享同一项目身份图标。不引入 `flutter_svg` 或额外图标资产。

思考态不复用 Lucide 图标，而由 `CustomPainter` 绘制固定中心的花形帧动画，避免 Unicode 字形差异和水平位移；普通活动 running 继续使用 Flutter 原生 `CircularProgressIndicator`。不使用 `flutter_animate`；入场动效被移除，保留花形思考动画、`SignalPressEffect` 和其他已有原生反馈。

必须统一的首批图标：menu、more-horizontal、plus、chevron-left/right/down、arrow-up、stop-square、rotate-cw、monitor、monitor-off、terminal、file-diff、check、alert-circle。

## 实现进度与后续顺序

浅色 / 深色色板已覆盖主要页面、设置、Markdown 与工作区。外观选择和系统跟随由独立控制器处理，不替换会话子树。原有会话搜索、消息定位、IME 优化、权限与恢复语义继续保留；后续验收重点是 Android 真机上的系统字体、键盘、系统栏与小屏布局。

### Phase 1：设计基础与主控制台

- 重写 `signal_console_theme.dart` 的色彩、排版、圆角与基础按钮主题。
- 重构 `ConnectionHeader`、`MessageBlock`、`AssistantBubbleFrame`、`ActivityBlock` 和 `PromptBar`。
- 删除不再使用的 `LegacyConnectionHeader`、Signal Console 吉祥物、彩色偏移阴影与旧装饰 painter。
- 保持网络、transcript、附件、命令筛选和 Stop 行为不变。

### Phase 2：主流程页面

- 重构 `PairScreen` 与 `PairReviewSheet`。
- 将 `SessionNavigatorPage` 重做为独立三视图页面：默认会话视图、项目子视图和搜索子视图；项目与会话使用扁平列表和 Phosphor Fill 身份图标。项目切换使用可降级的 shared-axis，搜索使用 AppBar 展开与轻微缩放淡化。
- 将 `PermissionRequestCard` 升级为 04 权限决策体验。
- 重构 `WorkspaceDrawer` 的文件列表和 Diff 视图。

### Phase 3：恢复与终态

- 已用纯展示映射覆盖离线、失败、停止中、已停止和停止超时；停止/失败终态从当前轮权威 transcript 证据推导，不新增第二套全局状态源。
- 已用共享 `RecoveryStatePanel` 统一事实说明、保留内容和单一主动作的位置；停止超时可再次停止，失败可恢复上条指令进入编辑，已停止可进入只读工作区。
- 已对本地 transcript、草稿与重连信息建立可测试的显示规则；未确认 prompt 仍沿用客户端重发协议。
- 仅在未来定义真实重试耗尽策略后增加 11 重连失败终态。

### Phase 4：清理与可访问性

- 清理旧 token、旧组件和过时测试文案。
- 验证 48px 触控、屏读标签、live region、焦点顺序和非颜色状态表达。
- 真机检查系统默认中文字体、键盘、小屏、横屏、大字体与减少动态效果。

## 测试与验收

每个阶段至少运行：

```powershell
cd mobile
flutter analyze
flutter test
```

新增或更新的组件测试必须覆盖：

- 紧凑会话头在 390×844、小屏和大字体下不溢出。
- Composer 交互控制视觉可为 36px、实际命中区至少 48px，键盘出现不遮挡；权限图标可直接打开模式选择，上下文余量具有完整屏读语义。
- 键盘从关闭进入打开状态时允许一次状态切换；后续连续 inset 帧不得重复重建已渲染消息与 Composer，指令建议必须在剩余高度内自适应且无溢出。
- “···”菜单不显示上下文 token，保留模型名时具有“当前模型”屏读语义。
- 思考态使用固定中心的花形帧动画，关闭系统动画时固定为完整花形；其他活动 running 仍使用原生进度指示器，测试结束无 pending Timer。
- 权限页仅允许一次或拒绝，处理中禁用重复点击；有路径时展示工作目录，缺失时展示 fallback 文案。

- stopping、stopped 和 stop-timeout 三态互不混淆。
- error、offline、connecting、stopping 等状态不只靠颜色。
- Diff 在长路径、长代码行和大字体下仍可阅读。
- 减少动态效果时关闭连续动画。
